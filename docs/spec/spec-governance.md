# VOIDHAVEN V0 — 规则对照表

> Purpose: prevent cross-document conflicts during V0 implementation. This table records the single final owner for each rule category.

| 规则类别 | 最终责任文档 | 实现约束 |
|---|---|---|
| 产品定位、V0 范围、核心用户路径、隐私规则、是否新增功能 | `VOIDHAVEN V0 前端开发说明.md` | 其中的 `[冻结]` 决策优先；不得因页面实现或视觉参考改变。 |
| 路由、逐页信息结构、页面状态、页面交互、`OPEN_QUESTION` | `page-spec.md` | 作为逐页施工依据；不得将 `[默认]` 或视觉建议升级为新的产品冻结规则。 |
| 配色、排版、间距、组件外观、视觉层级、响应式呈现 | `design01.md` | V0 已确认采用“经典白 / Notion 式质感”；仅解决视觉冲突，不得改变页面信息架构。 |
| 前端领域类型、Mock 数据形状、查询条件、Service 边界 | `mock-data-contract.md` | 仅覆盖竞赛与组队公开业务数据；后续 HTTP 数据必须映射到同一前端领域类型。 |

## 关键规则的落点

| 产品规则 | 逐页规则 | 视觉规则 |
|---|---|---|
| 首页真实信息优先，竞赛与组队直接联动 | 首页桌面端“近期竞赛 / 正在组队”双栏，移动端按顺序纵向堆叠 | 浅色中性界面、居中壳层、轻边框、紧凑信息行；Hero 不遮挡首屏真实信息。 |
| Footer 必须提供探索、项目、社群 / 联系、版权入口 | Global Footer 在主要页面统一存在 | 使用紧凑文字分组、低对比层级和移动端压缩布局；不得为贴近参考图而删入口。 |
| Header 只提供 Logo、竞赛、组队、投稿、加入我们、关于 | Global Header 的路由与 active 状态按 `page-spec.md` 实现 | 保持浅色、单行、轻分隔；不因参考图增加未定义的工具图标或新导航。 |
| 详情页信息必须服务于判断与后续行动 | 各详情页依照自身信息结构，不存在 ID 显示 404 | 不强制套用首页双栏；以可读性、内容韧性和单列移动端为准。 |
| 公开页面不得暴露私人联系方式 | Team Detail 联系 CTA 进入中转流程；投稿渠道、404、关联竞赛可点击性维持 `OPEN_QUESTION` | 视觉表达不得暗示或新增私信、登录、联系人信息等 V0 外功能。 |

## 冲突处理顺序

1. 产品说明中的 `[冻结]` 产品决策；
2. V0 核心用户路径与前后端接口契约；
3. `page-spec.md` 的逐页信息结构和已冻结交互；
4. 可用性与响应式体验；
5. `design01.md` 的视觉系统；
6. 工程实现便利。

未冻结问题必须记录为 `OPEN_QUESTION`，不得以视觉方案已确认为由自动决定。
